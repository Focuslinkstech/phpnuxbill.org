خذ نسخة احتياطية قبل كل تحديث. يغيّر التحديث قاعدة البيانات، والنسخة الاحتياطية هي طريق العودة الوحيد.

## ما الذي تنسخه

| ماذا | لماذا |
|---|---|
| قاعدة البيانات | العملاء والباقات والمعاملات والإعدادات. |
| `config.php` | بيانات دخول قاعدة البيانات و`APP_URL`. وليس ضمن ملفات التنزيل. |
| `system/uploads/` | الشعارات والملفات المرفوعة والإعدادات المخزنة كملفات. |
| كل ما أضفته | الإضافات في `system/plugin/` وبوابات الدفع في `system/paymentgateway/` والقوالب المخصصة في `ui/`. |

### قاعدة البيانات

الطريقة الموثوقة هي أخذ dump من الخادم:

```bash
mysqldump -u phpnuxbilluser -p phpnuxbill > phpnuxbill-$(date +%F).sql
```

من **Settings > Backup/Restore** يستطيع SuperAdmin أيضًا تنزيل جداول مختارة كملف JSON ورفع ملف للاستعادة. وهي مفيدة لنقل البيانات، لكن تعامل معها بحذر: الاستعادة **تفرّغ كل جدول في الملف قبل تحميله**. لا تعتمد عليها نسخةً احتياطية وحيدة، وجرّب الاستعادة على نسخة أولًا.

## التحديث

1. خذ النسخ الاحتياطية أعلاه.
2. ارفع الإصدار الجديد فوق القديم. احتفظ بـ `config.php` و`system/uploads/` والمجلدات التي أضفتها.
3. افتح `/update.php` في المتصفح. ينفّذ تغييرات قاعدة البيانات الجديدة من `system/updates.json` ويسجّل الإصدار في `version.json`.
4. احذف الملفات داخل `ui/compiled/` و`ui/cache/`.
5. سجّل الدخول وافحص لوحة التحكم وصفحة عميل وودجت cron.

اقرأ [ملاحظات الإصدار](/ar/changelog/) أولًا. فهي تذكر ما تغيّر.

## التراجع

1. أعد الملفات القديمة.
2. استعد قاعدة البيانات من الـ dump:

   ```bash
   mysql -u phpnuxbilluser -p phpnuxbill < phpnuxbill-2026-01-01.sql
   ```

3. امسح `ui/compiled/` و`ui/cache/`.

لا تشغّل إصدارًا أقدم على قاعدة بيانات أحدث دون استعادة الـ dump. فالشيفرة الأقدم لا تعرف الأعمدة الجديدة.
