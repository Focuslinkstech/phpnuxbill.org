يشرح هذا الدليل أقصر طريق من تثبيت جديد إلى عملية بيع تعمل: أضف راوتر Mikrotik، وأنشئ باقة، ثم اشترِها بقسيمة كعميل تجريبي. يفترض أنك أنهيت [التثبيت](/ar/docs/getting-started/installation/) وتستطيع تسجيل الدخول كمدير.

## 1. جهّز الراوتر

يتحدث PHPNuxBill مع راوتر Mikrotik عبر واجهة RouterOS API.

- **فعّل خدمة API.** في WinBox افتح *IP > Services* وتأكد من تفعيل `api`. منفذها الافتراضي `8728`.
- **أنشئ مستخدمًا لـ PHPNuxBill** على الراوتر. المستخدم المخصص أفضل من `admin`. الصلاحيات الكاملة أبسط للبداية، ويمكنك تقييدها لاحقًا عندما تعرف ما يحتاجه إعدادك.
- **تأكد من أن الخادم يصل إلى الراوتر** عبر هذا المنفذ. إذا كان PHPNuxBill على استضافة بعيدة فستحتاج عادةً إلى قاعدة جدار ناري أو VPN ليكون منفذ API متاحًا للخادم، لا للجميع.

## 2. أضف الراوتر

افتح *Network > Routers* وأضف راوترًا:

| الحقل | ما تكتبه |
|---|---|
| Status | Enable |
| Router Name / Location | اسم تتعرّف عليه، مثل المكان الذي يخدمه |
| IP Address | عنوان الراوتر، مع المنفذ إن لم يكن الافتراضي: `192.168.88.1` أو `192.168.88.1:8728` |
| Username | مستخدم RouterOS الذي أنشأته |
| Router Secret | كلمة مرور ذلك المستخدم |
| Description | اختياري، مثل المنطقة التي يغطيها |

اترك *Test Connection* مفعّلًا واحفظ. إذا فشل الاختبار فستوضح الرسالة السبب. الأسباب المعتادة: خدمة API متوقفة، أو منفذ خاطئ، أو كلمة مرور خاطئة، أو جدار ناري في الطريق.

## 3. أنشئ ملف عرض نطاق (Bandwidth)

افتح *Internet Plan > Bandwidth* وأضف ملفًا: اسمًا وسرعة التنزيل والرفع. تختار الباقات أحد هذه الملفات، فيمكنك إعادة استخدام السرعة نفسها في عدة باقات.

## 4. أنشئ باقة

افتح *Internet Plan > Hotspot* (أو *PPPOE*) وأضف باقة:

- **Active** و**Prepaid**، مع **Personal** أو **Business** كنوع للباقة.
- **Plan Name** يراه العملاء.
- **Unlimited**، أو **Limited** بالوقت أو بالبيانات أو بكليهما.
- ملف **Bandwidth** من الخطوة السابقة.
- **Package Price** ومدة الباقة (**Validity**).
- **Router** الذي أضفته.

احفظها. تُنشأ الباقة على الراوتر نيابةً عنك.

## 5. اختبر بقسيمة

1. افتح *Services > Vouchers* وأضف قسيمة واحدة للباقة الجديدة. تشرح صفحة [القسائم](/ar/docs/using/vouchers/) النموذج.
2. افتح بوابة العميل، وسجّل عميلًا تجريبيًا، وأدخل الرمز في *Voucher Activation*.
3. يُنشأ الحساب على الراوتر. صِل جهازًا بالهوت سبوت وسجّل الدخول للتأكد من أن كل شيء يعمل.

## 6. أعدّ مهمة cron

لا تنتهي الباقات في وقتها إلا عند تشغيل [مهمة cron](/ar/docs/getting-started/installation/). افعل ذلك الآن قبل وصول العملاء الحقيقيين.

## إذا حدث خطأ

| ما تراه | ما تتحقق منه |
|---|---|
| فشل *Test Connection* | خدمة API مفعّلة، والمنفذ صحيح ومتاح من الخادم، واسم المستخدم وكلمة المرور صحيحان. |
| اشترى عميل باقة لكنه غير متصل | الباقة تحمل الراوتر المتوقع، واتصال الراوتر ما زال يعمل، ولا يُظهر *Logs* خطأً لذلك العميل. |
| باقة لا تنتهي | مهمة cron تعمل. تنبّهك لوحة التحكم إذا لم تعمل لمدة 24 ساعة. |
| تعرض صفحة خطأً فارغًا | على جهاز اختبار، غيّر `$_app_stage` في `config.php` إلى قيمة غير `Live` لترى الخطأ الحقيقي. |

ما زلت عالقًا؟ راجع [الحصول على المساعدة](/ar/docs/getting-started/getting-help/).
